## 1. 연결 전 체험: 간단 테스트

1. 파일을 압축 해제한 뒤 폴더를 웹서버로 실행합니다. 예: VS Code Live Server 또는 이 폴더에서 `python -m http.server 8000`.
2. `http://localhost:8000` 주소로 접속합니다.
3. 학생으로 1모둠을 선택해 이름·활동을 저장하고, 처음으로 돌아와 교사 모드에서 `00000`을 입력합니다.
4. 교사 화면에서 저장된 1모둠 활동을 확인할 수 있습니다.

**중요: 이 체험 모드는 같은 브라우저의 저장소(localStorage)만 사용합니다. 다른 기기에서는 보이지 않습니다.** HTML 파일을 더블클릭해서 열 경우 브라우저에 따라 저장·동작 제약이 있을 수 있으므로 웹서버 실행을 권장합니다.

## 2. 서로 다른 학생 태블릿과 교사 전자칠판 연결: Supabase 필수

1. [Supabase](https://supabase.com/)에서 프로젝트를 만듭니다.
2. SQL Editor에서 이 폴더의 `schema.sql` 전체를 실행합니다. 기존 앱에 사용하던 Supabase 프로젝트라면 이 SQL이 모둠 테이블의 정책을 간편 입장 버전으로 교체합니다.
3. Authentication → Sign In / Providers에서 **Anonymous Sign-ins**를 켭니다. 이것은 사용자가 입력하는 로그인과 다릅니다. 학생 태블릿에 로그인 화면 없이 내부적으로 임시 세션을 부여하기 위한 기능입니다.
4. Connect 또는 Project Settings → API에서 Project URL과 **publishable key**(기존 프로젝트라면 anon key 가능)를 복사합니다.
5. `config.js`를 다음처럼 수정합니다.

```javascript
window.ECO_CONFIG = {
  SUPABASE_URL: 'https://YOUR-PROJECT.supabase.co',
  SUPABASE_PUBLISHABLE_KEY: 'sb_publishable_YOUR_KEY'
};
```

6. 다시 열면 여러 태블릿에서 활동을 공유할 수 있습니다. 학생은 계정 없이 모둠에 입장하고, 교사는 `00000`만 입력합니다. 교사 화면은 **3초 간격 자동 갱신**됩니다.
7. 운영할 때는 교사 화면에서 `새로고침` 버튼으로 수동 확인할 수도 있습니다.

**보안 주의:** `00000`은 매우 쉬운 PIN이므로 실습/시연에만 적합합니다. 교사 조회용 PIN은 서버의 `classroom_private.teacher_gate`에 저장되고 DB 함수에서 검사되지만, 단순 PIN 자체가 접근 보안을 강하게 제공하지는 않습니다. 학생 이름은 가급적 **별칭**을 입력하고, 개인정보·민감정보는 수집하지 마세요. 실제 학교 공개 서비스는 PIN 강화, 호출 제한, 수업 코드/접근 제어가 필요합니다. `secret`/`service_role` 키를 GitHub에 넣지 마세요.

PIN을 바꾸려면 Supabase SQL Editor에서:

```sql
update classroom_private.teacher_gate set pin='63821' where id=1;
```

(변경 후 교사 화면에서 새 PIN을 입력해야 합니다. 로컬 체험 모드의 PIN은 `00000`으로 고정되어 있습니다.)

**참고:** 학생별 가입·로그인 과정은 없지만 Supabase의 익명 세션(Auth anonymous)을 기술적으로 사용합니다. 익명 세션만으로는 모둠 자체에 대한 강한 소유권 증명이 되지 않으므로, 학생이 다른 모둠 번호를 선택해 수정할 수 있습니다. 모둠당 태블릿 하나 사용을 권장합니다.

## 3. GitHub Pages 배포

1. GitHub에 저장소 하나를 만듭니다.
2. 이 폴더 **내부의 파일을 모두 저장소 최상위에 업로드**합니다(`index.html`이 최상위).
3. Settings → Pages → Deploy from a branch → `main` / `/(root)` 선택.
4. 생성된 `https://아이디.github.io/저장소이름/` 주소를 **교사와 학생에게 똑같이** 안내합니다.
5. 첫 화면에서 교사는 교사 모드·학생은 학생 모드를 선택합니다.

## 기존 버전에서 업데이트할 때

- GitHub Pages의 기존 파일을 이 ZIP 내용으로 교체하고 브라우저 새로고침(캐시가 남으면 Ctrl+F5)하세요. `schema.sql` 구조는 이전 무로그인 버전과 동일하며, 데이터는 `activity` JSON 안에 분류 결과 항목만 추가됩니다. v4는 카드가 12종 늘어나므로 기존의 16종 완료 결과만 자동으로 초기화됩니다.

- Supabase에 연결하지 않은 로컬 체험 모드의 교사 화면은 같은 브라우저에 저장된 활동만 볼 수 있습니다. 별도 기기에서 보려면 Supabase가 필요합니다.

## v5 PC·태블릿 대응 점검

- 동일한 GitHub Pages 주소를 PC의 Chrome/Edge, 태블릿의 Chrome/Safari에서 접속합니다. 별도 앱 설치가 필요하지 않습니다.
- 분류 활동: PC는 마우스 끌어 놓기, 태블릿은 터치로 끌거나 **카드 탭 → 분류 영역 탭**을 사용합니다. 그림 카드가 많기 때문에 태블릿에서는 탭 방식을 권장합니다. 분류 카드가 화면 아래로 더 이어질 경우 카드 목록 오른쪽의 ↑↓ 버튼으로 목록을 스크롤할 수 있습니다.
- 먹이그물: PC/태블릿 모두 카드를 눌러 활동판에 추가합니다. **연결 모드**에서는 출발 카드와 도착 카드를 차례로 누르고, 일반 모드에서는 카드를 끌어 이동합니다.
- 고정 크기 활동판(1050 × 880)은 작은 화면에서 **가로·세로 스크롤**로 탐색합니다. 태블릿은 가로 방향으로 놓으면 편리합니다. 빈 공간을 밀어 화면을 이동할 수 있습니다.
- 터치 조작 영역(버튼, 삭제 버튼) 확대 및 가로 폭별 카드·분류판 배치를 조정했습니다.
- 각 모둠의 태블릿과 교사의 PC 사이에 활동을 공유하려면 **Supabase 설정이 반드시 필요**합니다. 연결하지 않으면 각 기기별 로컬 체험 모드로 동작합니다.
- 학교에서 실제 사용하기 전 해당 태블릿 기종·브라우저와 교실 Wi-Fi 환경에서 카드 드래그, 연결, 실시간 저장을 직접 점검하세요.


## v6 추가: 먹이사슬·먹이그물 실행 취소 및 전체 지우기

- **↶ 되돌리기**: 생물 카드 추가/이동/삭제, 먹이 관계 추가/삭제, 화살표만 지우기, 전체 지우기를 작업 단위로 **최대 50단계**까지 취소합니다. 카드 이동은 이동 한 번이 한 단계입니다.
- **↷ 다시 실행**: 되돌린 작업을 복구합니다. 새 조작을 하면 다시 실행 기록이 초기화됩니다.
- **화살표만 지우기**: 카드 배치를 유지하고 연결선만 삭제합니다(확인 후 실행). 되돌릴 수 있습니다.
- **전체 지우기**: 먹이그물 활동판의 모든 생물 카드와 화살표를 한 번에 삭제합니다(확인 후 실행). **28장 구성요소 분류 기록과 '우리 모둠의 설명' 문장은 유지**됩니다. 전체 지우기도 바로 되돌릴 수 있습니다.
- **PC 단축키**: 먹이그물에서 `Ctrl+Z`(Mac `⌘Z`)는 되돌리기, `Ctrl+Shift+Z`(Mac `⌘⇧Z`)는 다시 실행. 글 입력 중에는 브라우저 기본 기능을 유지합니다.
- **태블릿**: 손가락으로 누르기 쉬운 크기의 버튼으로 동일 기능 사용.
- **저장 방식**: 되돌리기와 전체 지우기 후에도 기존 로컬 저장 또는 Supabase 자동 저장이 동작합니다. 작업 이력 자체는 현재 웹페이지 메모리에만 보관되므로 **페이지 새로고침·재입장 후에는 이전 작업의 실행 취소가 불가능합니다**. 서로 다른 태블릿에서 같은 모둠에 동시에 편집하는 상황은 권장하지 않습니다.
- **기존 데이터**: 기존 모둠별 분류 및 활동 내용은 그대로 유지됩니다. Supabase DB 스키마는 변경되지 않습니다.
